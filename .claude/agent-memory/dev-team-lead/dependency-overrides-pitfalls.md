Lessons from the 2026-09-30 `/dependabot` orphan-alert spec:

- **Unscoped overrides go stale and can pin the vuln themselves.** `"js-yaml": "4.3.1"` was once a fix and later _was_ the vulnerable version. Range-scoped overrides (`pkg@>=X <patched`) need their upper bound moved on each new advisory. Always diff the override bounds against GHSA ranges (`gh api /advisories/<GHSA>`); exact-match advisories (e.g. `= 3.1.6`) can fall outside an old range.
- **Global overrides silently beat workspace direct deps.** npm raises EOVERRIDE only for root direct deps. A workspace (`client`) declaring `^6.0.0` got 5.2.6 from a global `"webpack-dev-server": "5.2.6"`, with no error. The same trap applied to `http-proxy-middleware`, where a global 3.0.7 pin broke 6.x's `^4.1.1`. When bumping a workspace dep across majors, grep the root `overrides` for it _and for its dependencies_.
- **Bundled deps (`inBundle: true`, e.g. under `node_modules/npm/`) cannot be overridden.** The only remedy is an upstream release that bundles a fixed version; otherwise recommend a dismissal. Verify with `npm pack npm@<v>` and read the bundled `package.json`.
- **Dependabot never moves single-version override pins.** `konva`/`react`/`react-dom` are pinned in root `overrides` (guarded by `scripts/check-single-dep-version.sh`). A grouped bump (#2095/#2115) raised the workspace specifiers but left the overrides, so npm forced react 19.2.8 under react-konva 19.3.0 → client render crash in E2E. Any bump of a pinned package must move its override in the same commit.
- **Dead override keys exist.** `"gray-matter": {...}` matched nothing (only `@11ty/gray-matter` is installed). Check that an override's key appears in the lockfile before keeping it.
- **Removing an override is not enough when a CLI tool loads the package (#2116).** `webpack-cli` does `import("webpack-dev-server")` from its own root-hoisted location, and `babel-loader` resolves its `@babel/core` peer the same way. When `docs/` (Docusaurus) needs the old major, it takes the root slot. The workspace's new major is then nested and never used, and nothing reports an error. Fix it with a **root devDependency hoisting anchor** at the same exact version (now in CLAUDE.md > Dependency Policy). Verify through the resolving parent (`npm ls <pkg>` should show `webpack-cli → <pkg>@<new> deduped`), not by checking that the workspace entry exists. webpack had the same trap (#2138, resolved: root `webpack` anchor plus CI `check-single-dep-version.sh konva webpack`).
- **#1823's "Babel 8.0.0 type-argument regression" was a misdiagnosis.** A Babel 8 preset running under a Babel 7 core strips annotations but leaves `foo<T>()` / `new Foo<T>()`, because Babel 8 renamed Call/NewExpression `typeParameters` to `typeArguments`. A pure 8.x graph strips them correctly. When a major bump "half works", check for a mixed-major graph before blaming upstream.
- **A green build plus green Jest does not prove a transpiler major (#1823).** Jest runs ts-jest, never babel-loader, so it cannot see bundle output. Babel 8 `preset-react` derives `development` from envName (babel-loader does not map webpack's mode), so prod shipped `jsxDEV` from `react/jsx-dev-runtime`, which is `void 0` under NODE_ENV=production: build green, app dead on first render. `preset-typescript@8` defaults `onlyRemoveTypeImports: true`, which turned `import { type X }` into side-effect imports and changed the module graph (+8 CSS-order warnings). Grep the prod bundle for dev runtimes and diff chunk hashes/warning counts against a baseline build. Also: a later `--mode development` build overwrites `client/dist`, so re-check the prod bundle yourself rather than trusting a dist left behind.
- **Never pin `.nvmrc` to a minor to satisfy an engine floor.** setup-node resolves `24.11` to the latest 24.11.x, which would downgrade CI from 24.21. Raise `engines` instead and keep `.nvmrc` at the major.

**Why:** these pitfalls turned a "bump 4 transitive deps" task into a cascade across 3 other override entries.
**How to apply:** in any dependency or Dependabot spec, audit the full `overrides` block, not just the alerted package.
